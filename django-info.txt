ساخت پروژه‌ی فروشگاهی جنگو — «فروش پروژه‌ی ربات دیوار»

خلاصه‌ هدف:
ساخت یک وب‌سایت فروشگاهی مبتنی بر Django برای عرضه و فروش نسخه‌های مختلف «ربات دیوار» (رباتی که با tkinter ساخته شده و به‌صورت فایل zip/نصب‌شده توسط Inno Setup عرضه می‌شود). سایت باید کاملاً RTL و فارسی، مینیمال، با تم Glassmorphism، و طراحی بسیار جذاب و کاربرپسند باشد. پرداخت آنلاین با درگاه زیبال (Zibal) انجام شود. سیستم لایسنس به‌صورتی پیاده‌سازی شود که هر خریدار بتواند محصول را فقط روی یک سیستمِ مشخص نصب و فعال کند و امکان انتقال/فروش مجدد غیرمجاز بسیار دشوار باشد. سیستم همکاری در فروش (افلیت) با قابلیت درصددهی و گزارش‌گیری فراهم شود. محتوای صفحات طبق فایل @امکانات.txt قرار گیرد.

طراحی و تجربه کاربری (UI/UX)

زبان سایت: فارسی، راست‌به‌چپ (RTL) در تمام صفحات و فرم‌ها.

استایل کلی: مینیمال + Glassmorphism (شیشه‌ای) — استفاده از سایه‌ها و بلورهای نرم.

تمام CSS پروژه باید در یک فایل CSS مرکزی قرار بگیرد و همه‌ی صفحات از آن ارث‌بری کنند. ساختار قالب باید با base.html طراحی شود و تمامی قالب‌ها از آن ارث ببرند.

طراحی واکنش‌گرا (mobile-first) و با توجه به دسترسی (accessibility) حداقل سطح AA.

صفحات و معماری اطلاعات

صفحه‌ی اصلی (فروشگاهی): لیست محصولات، فیلتر و جستجوی ساده، بنر معرفی.

صفحه‌ی محصول:

عنوان، توضیحات طولانی (HTML-rich)، امکانات (structured list)، قیمت‌ها/پلان‌ها (مثلاً استاندارد، پرو، لایسنس مادام‌العمر/سالیانه)، ویدئو معرفی، گالری تصاویر، دمو/تصاویر اسکرین‌شات، فایل‌های قابل‌دانلود (پس از خرید).

دکمه‌ی خرید -> انتخاب پلن -> صفحه پرداخت.

داشبورد کاربر: محصولات خریداری‌شده، وضعیت لایسنس‌ها، لینک دانلود (محدود/قابل تمدید)، تاریخچه خرید، اطلاعات پرداخت، دریافت فاکتور، امکان درخواست پشتیبانی.

داشبورد فروشنده/مدیر: مدیریت محصولات، مدیریت سفارش‌ها، مدیریت لایسنس‌ها، گزارش‌گیری فروش، مدیریت مشاوران/همکاری در فروش، پنل پرداخت‌های تسویه‌حساب برای افیلیت‌ها.

صفحات عمومی: درباره ما، تماس با ما (فرم و اطلاعات تماس)، مقالات/بلاگ (با امکان مدیریت محتوا و SEO).

جریان پرداخت و وب‌هوک (Zibal)

ادغام با API درگاه زیبال (Zibal) برای پرداخت آنلاین:

ساخت تراکنش در سرور، نگهداری مرجع، هدایت کاربر به صفحه پرداخت زیبال، دریافت وب‌هوک / redirect بعد از پرداخت.

اعتبارسنجی امن پرداخت با درخواست به API زیبال و بررسی نتیجه.

بعد از تایید پرداخت: تولید/اختصاص لایسنس، فعال‌سازی دانلود (لینک منقضی‌شونده)، ارسال ایمیل/نوتیف به کاربر و مدیر.

ذخیره و لاگ کامل وب‌هوک‌ها برای بررسی تراکنش‌ها.

سیستم لایسنس — الزامات و پیشنهاد فنی (شرح عملیاتی)

هدف: پس از خرید، خریدار یک فایل نصبی (که شما با Inno Setup ساخته‌اید) دریافت می‌کند؛ این نصبی باید فقط روی یک سیستم مشخص اجرا شود و انتقال یا اشتراک‌گذاری آسان نباشد.

پیشنهاد اجزای سیستم لایسنس:

تولید کلید لایسنس امن: هنگام پرداخت موفق، سرور یک کلید لایسنس تولید می‌کند (مثلاً UUID ترکیب‌شده با HMAC و تاریخ)، همراه با شناسه‌ی محصول و پلن.

فعال‌سازی مرحله‌ای (Activation):

برنامه‌ی دسکتاپ (Tkinter) هنگام اولین اجرا یا در صفحه فعال‌سازی، از کاربر می‌خواهد لایسنس را وارد کند.

برنامه اطلاعات سخت‌افزاری دستگاه را گرفته (مثلاً machine-id، MAC address (اولویت پایین‌تر)، CPU serial یا UUID سیستم) و یک fingerprint تولید می‌کند.

برنامه به API لایسنس سرور درخواست فعال‌سازی می‌دهد: POST /api/licenses/activate شامل {license_key, fingerprint, optional user info}.

سرور بررسی می‌کند که لایسنس معتبر، هنوز فعال‌نشده یا تعداد فعال‌سازی مجاز را پر نکرده باشد. اگر تایید شد، لایسنس به آن fingerprint قفل می‌شود.

محدودیت یک‌سیستمی: پلن به‌صورت پیش‌فرض مقدار مجاز فعال‌سازی = 1. می‌توان قابلیت «انتقال لایسنس» از داشبورد فراهم کرد با فرایندی امن (درخواست انتقال، تایید، حذف fingerprint قبلی و صدور fingerprint جدید).

بررسی دوره‌ای (Optional): برنامه دسکتاپ می‌تواند گهگاهی (مثلاً هر 7 روز) بدون آزار کاربر، با سرور چک کند که لایسنس هنوز معتبر است. اما برای حریم خصوصی، امکان فعال‌سازی آفلاین هم در نظر گرفته شود (مثلاً تولید کد فعال‌سازی آفلاین از پنل مدیر).

امنیت لایسنس:

کلیدها در DB با HMAC/Hash ذخیره شوند (نه بصورت متنی ساده).

ارتباطات API با TLS، امضا HMAC بین سرور و برنامه برای جلوگیری از جعل.

نرخ‌محدودیت (rate-limiting) برای endpointهای فعال‌سازی.

قابلیت مسدودسازی فوری لایسنس (مسدودسازی در صورت گزارش نقض).

تحویل فایل: بعد از پرداخت، لینک دانلود ZIP ارائه شود اما:

لینک‌ها منقضی‌شونده باشند (مثلاً 48 ساعت یا 3 دانلود).

فایل zip رمزگذاری یا حداقل بسته‌بندی شده تا بدون لایسنس استفاده ساده ممکن نباشد.

همراه با مستندات نصب و یک فایل README شامل کد لایسنس و نحوه فعال‌سازی.

نکته حقوقی/فنی: هیچ سیستمی ۱۰۰٪ ضد دورزدن نیست، اما با ترکیب fingerprint سخت‌افزاری، لاگ فعال‌سازی، و سیاست‌های مناسب می‌توان فروش مجدد را بسیار دشوار کرد. حتماً در مستندات توجه کاربر را به شرایط استفاده و تبعات نقض جلب کنید.

سیستم همکاری در فروش (Affiliates)

هر مشاور/افیلیت یک حساب با کد معرف دارد.

هر خریدی که با آن کد انجام شود ثبت می‌شود و در جدول AffiliateSale ذخیره شده و درصد کمیسیون محاسبه می‌شود.

تنظیم درصد: برای هر محصول یا عمومی قابل تنظیم باشد (مثلاً 10%).

داشبورد افیلیت: گزارش فروش، کمسیون‌های محاسبه‌شده، وضعیت پرداخت (پرداخت‌شده/در انتظار)، لینک رفرال.

امکان پرداخت دستی یا اتوماتیک (با تنظیم آستانه حداقل پرداخت). ذخیره اطلاعات برای واریز (شماره کارت بانکی).

تاریخچه و فاکتور برای هر کمیسیون.

مدیریت رسانه و فایل‌ها

استفاده از django-storages در صورت نیاز به آپلود به S3 / راهکار میزبانی ابری، در حالت ساده فایل‌ها در سرور ذخیره شوند.

تصاویر محصول: اندازه‌های متعدد (thumbnail) و بارگذاری lazy.

ویدئو: پشتیبانی از embed (YouTube) یا آپلود فایل و پخش از سرور/CDN.

محدودیت حجم آپلود و اعتبارسنجی نوع فایل.

افیلیت: گزارش‌ها و جزئیات.

مستندات API (OpenAPI/Swagger) برای استفاده‌ی داخلی و توسط تیم Desktop.
