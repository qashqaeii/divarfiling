--------------------------------------------------------------------------------
۱. تغییر معماری
--------------------------------------------------------------------------------

نسخه ۱ (قدیم):
  - phrase-list + boolean
  - owner phrase → فوراً genuine_personal (override بی‌قید)
  - بدون score، بدون confidence، بدون diagnostics

نسخه ۲ (فعلی):
  - Strong Rules + Weighted Signal Scoring + Conflict Resolution
  - analyze_advertiser_signal() → نتیجه کامل با diagnostics
  - detect_advertiser_signal() → همان API قبلی (فقط label)

--------------------------------------------------------------------------------
۲. ترتیب Classification
--------------------------------------------------------------------------------

  ۱. مشاور رسمی (premium-panel / business / نام آژانس) → consultant
  ۲. غیرشخصی → بدون برچسب
  ۳. شخصی → Scoring Engine:
       a. استخراج signals از متن نرمال‌شده
       b. جمع وزن با dedup per reason_code + cap per category
       c. اگر critical signal → disguised_consultant (very_high)
       d. اگر score >= 60 → disguised_consultant
       e. در غیر این صورت → genuine_personal

--------------------------------------------------------------------------------
۳. دسته‌بندی Signalها
--------------------------------------------------------------------------------

  CRITICAL DISGUISED (+110 تا +120):
    - agent_contact_restriction
    - professional_broker_identity
    - structured_broker_metadata
    - broker_branding
    - inventory_language_critical

  STRONG DISGUISED (+75 تا +90):
    - inventory_language

  MEDIUM DISGUISED (+25 تا +45):
    - professional_workflow_language

  SOFT DISGUISED (+15 تا +40):
    - brokerage_sales_language

  OWNER (-15 تا -50):
    - explicit_owner_claim
    - owner_language
    - soft_owner_language

--------------------------------------------------------------------------------
۴. جدول وزن‌های مرکزی (DETECTOR_WEIGHTS)
--------------------------------------------------------------------------------

  critical_disguised  = +110
  strong_disguised    = +75
  medium_disguised    = +35
  soft_disguised      = +15
  explicit_owner      = -50
  owner               = -30
  soft_owner          = -15

  Threshold disguised = 60

--------------------------------------------------------------------------------
۵. Critical Override Rules
--------------------------------------------------------------------------------

این reason_codeها بدون توجه به owner claim، disguised می‌سازند:

  - agent_contact_restriction
  - professional_broker_identity
  - structured_broker_metadata
  - broker_branding
  - inventory_language_critical

مثال:
  «مالک هستم + همکاران تماس نگیرید» → disguised_consultant
  «سند به نام خودم + مشاوران تماس نگیرند» → disguised_consultant

--------------------------------------------------------------------------------
۶. Agent Contact Restriction (مهم‌ترین signal بازار ایران)
--------------------------------------------------------------------------------

Regex bounded: [agent target] + [optional polite/adjective] + [contact prohibition]

Agent targets:
  همکار / همکاران / همکارها / همکارای
  مشاور / مشاوران / مشاور املاک
  املاک / املاکی / دفتر املاک / بنگاه / آژانس / واسطه / دلال

Prohibition verbs:
  تماس نگیر / نگیرید / نگیرند / نفرمایید / نکنید
  زنگ نزن / نزنید / نزنند
  پیام ندهید / مزاحم نشوید

reason: agent_contact_restriction

نکته business rule:
  «املاک تماس نگیرد» در این پروژه disguised است (نه owner signal).

--------------------------------------------------------------------------------
۷. Inventory Language
--------------------------------------------------------------------------------

عباراتی مثل «فایل مشابه موجود»، «کد فایل 123»، «موارد مشابه»

reason: inventory_language / inventory_language_critical

--------------------------------------------------------------------------------
۸. Owner Signals
--------------------------------------------------------------------------------

دیگر unconditional override نیستند.

Explicit (-50): مالک هستم، سند به نام خودم، ...
Medium (-30): فروش توسط مالک، مستقیم از مالک، ...
Soft (-15): بدون واسطه، بدون دخالت مشاور، ...

«بدون دخالت مشاور» owner است و disguised از زیررشته «مشاور» نمی‌سازد (masking).

--------------------------------------------------------------------------------
۹. جلوگیری از Double Counting
--------------------------------------------------------------------------------

  - per reason_code: فقط max weight
  - REASON_SCORE_CAPS برای هر category
  - diagnostics همه matchها را نگه می‌دارد

--------------------------------------------------------------------------------
۱۰. Confidence
--------------------------------------------------------------------------------

  critical signal        → very_high
  score >= 100           → very_high
  score >= 60            → high
  score >= 40            → medium
  کمتر                   → low

--------------------------------------------------------------------------------
۱۱. API
--------------------------------------------------------------------------------

  analyze_advertiser_signal(...)  → AdvertiserSignalResult (کامل)
  detect_advertiser_signal(...)   → str (backward compatible)
  has_owner_markers(...)          → bool
  has_disguised_consultant_markers(...) → bool

--------------------------------------------------------------------------------
۱۲. فیلتر UI (بدون تغییر contract)
--------------------------------------------------------------------------------

  genuine_personal      → مالک واقعی
  disguised_consultant  → مشاور پنهان
  consultant / 1        → مشاور رسمی
  personal / 0          → همه شخصی‌ها
